# PhantomNet: Generative Cyber-Deception (LLM Honeypots)

An SSH honeypot whose shell is emulated by a Large Language Model. Instead of a fixed set of canned replies
(Cowrie-style), the LLM improvises believable terminal output for *any* command, while a deterministic layer keeps
session state consistent and a guardrail layer stops the model from revealing it is an AI. Every attacker action is
logged and mapped to MITRE ATT&CK.

```
attacker --SSH--> asyncssh server --> HoneypotEngine --+--> local fast-path (cd, pwd, mkdir, whoami ...)
                                                       +--> guard.check_input  (prompt-injection / AI fingerprinting)
                                                       +--> per-session cache  (idempotent cmds stay identical)
                                                       +--> LLM backend (Anthropic | OpenAI-compatible/Ollama | Mock)
                                                       +--> guard.sanitize_output (leaks, markdown, length)
                                                       +--> JSONL logger + ATT&CK tagger --> analysis.py
```

## Quick start
```bash
pip install -r requirements.txt
python -m pytest -q                     # 9 tests incl. a real SSH end-to-end test
python -m phantomnet.server             # mock backend, listens on :2222
ssh -p 2222 root@localhost              # password: 123456  (or anything on the 2nd attempt)

# real LLM
export ANTHROPIC_API_KEY=...            # then set backend: anthropic in config.yaml
# or local model via Ollama: backend: openai, model: llama3.1:8b

python -m phantomnet.analysis logs/phantomnet.jsonl   # threat summary
python -m eval.evaluate --backend mock                # evaluation harness
docker compose up --build                             # hardened container deployment
```

## Safety / deployment notes
* The honeypot **never executes** attacker commands; everything is text generated by the model.
* Run it on an isolated VM/VLAN, never with real credentials or data on the host. The compose file drops all
  capabilities and uses a read-only filesystem.
* The system prompt forbids real secrets and functional malware; output is also filtered by `guard.py`.
* Only deploy on infrastructure you own/are authorised to use; check your organisation's policy on logging attacker IPs.

## Layout
| Path | Purpose |
|---|---|
| `phantomnet/server.py` | SSH front-end, auth policy, interactive + `ssh host cmd` sessions |
| `phantomnet/engine.py` | Decision pipeline (local -> guard -> cache -> LLM -> sanitise -> log) |
| `phantomnet/persona.py` | Host persona + system prompt, MOTD |
| `phantomnet/guard.py` | Prompt-injection detection and output sanitising |
| `phantomnet/llm.py` | Backends: Anthropic, OpenAI-compatible, Mock |
| `phantomnet/logger.py` | JSONL events + MITRE ATT&CK tagging |
| `phantomnet/analysis.py` | Log -> markdown summary |
| `eval/evaluate.py` | Attacker-playbook evaluation (leak rate, consistency, latency) |
| `docs/` | Architecture, progress tracker, evaluation results |
